# KeyFin · 생활 코칭 & FDT Workbench

소비 이력과 날짜가 맞는 금융 상태를 바탕으로 **지금 필요한 돈 관리 행동을 정하고, 선택한 계획을 다음에 다시 확인하는 로컬 서비스**입니다.

처음부터 예측·위험·최적화 모드를 고르게 하지 않습니다. 첫 화면은 다가올 결제, 계좌별 여유, 예산 사용, 이전에 정한 한도를 함께 확인하고 우선할 행동 하나를 제시합니다. 새 지출이나 늦어지는 입금이 있으면 실제 금액·날짜·계좌를 반영해 변경 전후를 비교합니다.

## 기본 사용 흐름

1. **자료 연결·갱신:** 거래 CSV와 같은 날짜의 계좌 잔액·카드 미결제액·예산을 등록합니다. 자료가 오래됐으면 오늘의 사용 가능액을 추정해서 채우지 않습니다.
2. **생활 코칭 홈:** 다음 점검일까지 필요한 결제 준비, 보호할 돈, 예산 상태를 확인합니다. 문제가 없으면 불필요한 감축을 권하지 않습니다.
3. **행동 비교:** 구매/예정 지출, 자금 보관, 특정 입금 한 건의 지연, 기간별 추가 지출 한도를 비교합니다. 임의 감축률로 질문을 바꾸지 않습니다.
4. **선택과 재점검:** 사용자가 명시적으로 저장한 한도를 새 거래 자료와 비교합니다. 초과했으면 다음 계획을 재설정하고, 자료가 부족하면 성공 판정을 보류합니다.

| 화면 | 위치 |
|---|---|
| 생활 코칭, 행동 비교, 내 계획 점검 | `/` |
| 기존 자료 등록·갱신 및 전문 수치 분석 | `/workbench` |

기존 5개 수치 모드와 API는 전문 분석/회귀 검증용으로 유지합니다. 생활 코칭은 그 모드들을 사람 말로 이름만 바꾼 화면이 아니라, 독립된 행동·날짜·후속 관찰 계약을 사용합니다.

## 시작

Python 3.11 이상이 필요합니다. 기존 실행 방법을 그대로 사용합니다.

- Windows: `START.bat`
- macOS / Linux: `bash start.sh`

로컬 서버가 시작되면 브라우저의 첫 화면이 생활 코칭 홈으로 열립니다. 처음에는 **자료 연결·갱신 / 분석 도구**에서 CSV와 금융 스냅샷을 등록합니다. 기존에 만든 Twin도 그대로 사용할 수 있습니다.

개발·검증:

```bash
python -m pip install -r requirements-web.lock -e ".[dev]"
python -m pytest tests tests_web -q
node --check workbench/static/coach.js
```

## 계산과 표현의 원칙

통장 잔액, 카드 미결제액을 뺀 가용금액, 예산 잔여, 따로 보관할 돈을 구분합니다. 돈을 보관하는 행위를 소비로 처리하지 않고, 신용카드는 구매일과 출금일을 나눕니다. 특정 입금의 지연은 해당 한 건의 금액을 보존한 날짜 이동입니다.

400개 모델 경로에서 부족이 0회라는 결과는 현실 위험이 0%라는 뜻이 아닙니다. 하위 10% 지점은 최악의 경우나 보장 하한이 아닙니다. 기간 중 부족과 마지막 날 부족을 별도로 반환합니다. 잔액 증감의 설명은 중앙값 항목의 합이 아니라 경로 평균의 현금 정합식으로 제공합니다.

생활 코칭은 가까운 1~90일의 행동과 재점검에 집중합니다. 자동 은행 연결, 실제 이체·결제, 자동 알림 예약, 자유 문장 의미 해석, 인과적 절약 효과, 실세계 확률 보정은 제공한다고 주장하지 않습니다. 데모 자료의 잔액·예산·카드 정보는 가정이며 실제 계좌 확인 결과가 아닙니다.

## 구조

```text
fdt/coaching_contract.py     명시적 날짜·행동 입력 검증
fdt/coaching_projection.py   행동별 현금·미결제·보관·예산 장부
fdt/coaching.py              관측 → 우선 행동 → 변경 비교 → 재점검
workbench/coaching.py        코칭 API와 로컬 계획 저장
workbench/static/coach.*     기본 생활 코칭 화면
workbench/_numeric_app.py    보존된 기존 API/보안 구현
workbench/_numeric_jobs.py   보존된 기존 수치 작업 구현
```

수치 계산과 코칭 계산은 동일한 단일 spawn 작업·취소·타임아웃 정책을 공유합니다. 로컬 Host/Origin 검사, 세션 쓰기 토큰, 업로드 제한은 유지합니다. 사용자 계획은 `workbench_data/coaching.sqlite`에 별도로 저장하며 관측된 거래를 바꾸지 않습니다.
