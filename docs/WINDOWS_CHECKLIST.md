# Windows 실제 PC 인수 체크리스트

이 문서는 수행 결과가 아니라 Windows PC에서 확인할 항목이다. 이 환경에는 Windows 콘솔이 없어 아래 항목의 실제 수행 여부를 보장하지 않는다.

## 환경과 최초 실행

1. Windows 10/11, Python 3.11 이상 64-bit, Chrome/Edge 버전을 기록한다.
2. ZIP을 공백·한글이 포함된 경로에도 풀어 START.bat를 더블클릭한다.
3. .venv 생성 및 최초 의존성 설치가 끝나고 Open 주소가 출력되는지 확인한다.
4. 서버가 준비된 후 브라우저가 열리는지 확인한다. 실패하면 주소 직접 접속이 되는지 확인한다.
5. 추가 Node/npm/금융 API/LLM API 키 입력이 필요하지 않은지 확인한다.

## 생성과 실행

1. 소비001 CSV를 업로드하여 사용자 ID·거래 수·계좌/카드 ID가 보이는지 확인한다.
2. 데모001을 선택하고 USER_ASSUMPTION 배너가 있는지 확인한다.
3. 엔진을 생성하고 다섯 페이지를 각각 실행한다.
4. 원문 JSON 복사, 요청 JSON 저장·불러오기, 결과 파일 다운로드가 정상인지 확인한다.
5. 실제 브라우저 CSP로 스크립트/스타일이 차단되는 오류가 없는지 개발자 콘솔을 확인한다.
6. 모바일 폭 390px에서 모든 페이지의 body 가로 넘침이 없는지 확인한다.

## 종료와 복구

1. 유휴 상태에서 BAT 콘솔을 클릭하고 Ctrl+C를 누른다. [STOPPED]를 확인한다.
2. 재실행하여 저장된 Twin이 남고 같은 기본 포트가 사용 가능한지 확인한다.
3. 최적화 실행 직후 화면 작업 취소를 누르고 다음 실행이 가능한지 확인한다.
4. 최적화 도중 BAT 콘솔 Ctrl+C를 누른다. Workbench 부모/자식 Python 프로세스가 정리되는지 작업 관리자에서 확인한다. 다른 Python 작업은 영향을 받으면 안 된다.
5. 콘솔 `(Y/N)` 배치 종료 확인이 나타나면 서버 종료 메시지 이후인지 기록한다.
6. 브라우저만 닫으면 서버는 계속 실행되는지 확인한다.
7. 실행 중 새로고침하여 작업 복구·취소가 가능한지 확인한다.
8. 같은 폴더 START.bat를 두 번 실행하면 두 번째 인스턴스만 오류를 내는지 확인한다.
9. 포트 8765를 다른 프로그램이 쓰고 있으면 자동으로 다음 포트로 이동하는지 확인한다.

## 데이터 정리

정상 종료 후 workbench_data/uploads와 세션 jobs가 정리되고 twins는 유지되는지 확인한다. UI의 Twin 삭제는 명시한 항목만 제거해야 한다.
